# MVP-1.5 Interaction Calibration Design

## Status

Accepted for implementation on 2026-08-19. The user delegated minor parameter and implementation decisions to the main agent. Only changes to product direction, privacy/security boundaries, or major technology choices require another user decision.

## Goal

Make the existing MediaPipe-to-Three.js interaction reliable enough for a repeatable demo: a visible, stable pointer; intuitive selfie-mirrored control; reliable pinch selection; stable two-hand zoom/rotation; and deterministic trace replay for calibration.

## Scope

- Keep the camera preview selfie-mirrored.
- Map raw MediaPipe X explicitly so physical rightward motion moves the screen pointer right.
- Show a visible pointer, hit radius, and compact gesture state.
- Replace frame-only pointer smoothing with a timestamp-aware One Euro filter.
- Replace fixed-distance pinch with palm-normalized hysteresis and time-based state transitions.
- Replace per-frame two-hand deltas with baseline-relative zoom and rotation.
- Preserve Open Palm as cancel selection / collapse details.
- Preserve manual camera shutdown and 15-second no-hand automatic shutdown.
- Store all tunable values in a versioned calibration profile.
- Record and replay canonical hand frames for deterministic tests and tuning.

## Out of Scope

- Voice, RAG, LLM, Agent, and Obsidian writes.
- Direct world-coordinate hand mapping.
- A general gesture-programming framework.
- Automatic per-user calibration UI in this release.
- Replacing MediaPipe Hand Landmarker.

## Architecture

```text
MediaPipe Hand Landmarker
        ↓
HandFrame
        ↓
CoordinateMapper
        ↓
GestureEngine
├── PointerFilter
├── PinchStateMachine
├── OpenPalmStateMachine
└── TwoHandTransformStateMachine
        ↓
InteractionController
├── PointerPresenter
├── node hit testing / selection
└── bounded scene camera commands
```

### HandFrame

The tracker emits a canonical value independent of MediaPipe, DOM, and Three.js:

```ts
interface HandFrame {
  timestampMs: number;
  frameWidth: number;
  frameHeight: number;
  hands: TrackedHand[];
}

interface TrackedHand {
  landmarks: NormalizedLandmark[];
  handedness: 'Left' | 'Right' | 'Unknown';
  confidence: number;
}
```

Timestamps must be monotonic. Invalid or incomplete hands are dropped before gesture processing.

### CoordinateMapper

Coordinate conversion is explicit and tested:

```text
raw normalized camera x
→ mirrored display x = 1 - raw x
→ viewport pixel coordinate
→ Three.js NDC
```

CSS mirroring remains presentation-only. Scene hit testing never infers mirror behavior from CSS.

### Pointer filtering

`PointerFilter` is a small interface around two independent One Euro filters:

```ts
update(timestampMs, point): point
reset(): void
```

The implementation may vendor a small MIT implementation with attribution, but Auaka owns the interface, tests, profile, and dropout semantics.

Initial profile values:

- `minCutoff = 1.0`
- `beta = 0.007`
- `derivativeCutoff = 1.0`
- screen deadzone: 4 px
- cursor diameter: 12 px
- hit radius: 24 px

The hit-radius ring is visual feedback only in MVP-1.5. Selection continues to use the existing Three.js raycast; assisted picking and snapping are out of scope.

These are calibration defaults, not product constants.

### Pinch state machine

Pinch uses a scale-independent ratio:

```text
distance(thumb tip, index tip) / distance(wrist, middle MCP)
```

State flow:

```text
Idle → Candidate → Active → Release → Cooldown → Idle
```

Initial rules:

- Enter candidate at ratio `<= 0.32`.
- Activate after 120 ms continuously below the enter threshold.
- Emit exactly one selection event on activation.
- Enter release at ratio `>= 0.48`.
- Cool down for 150 ms after release.
- Cancel candidate on invalid hand, low confidence, dropout beyond grace, or two-hand mode.
- A pinch over empty space has no selection side effect.

### Open Palm

Open Palm cancels the active selection and collapses detail UI without resetting the scene camera. Recognition uses finger joint geometry in a palm-relative frame rather than assuming fingertips must be vertically above PIP joints.

- Stable hold: 250 ms.
- Cooldown: 500 ms.

### Two-hand transform

Two-hand mode enters after 200 ms of two valid open palms. Two arbitrary detected hands emit no transform commands. Stable handedness is preferred for identity; ambiguous crossing pauses updates rather than guessing.

At entry, capture distance, unwrapped angle, camera distance, and OrbitControls camera azimuth. Compute:

```text
zoom = log(currentDistance / baselineDistance)
rotation = unwrap(currentAngle - baselineAngle)
```

Initial safeguards:

- zoom deadzone: 3% from baseline
- rotation deadzone: 3 degrees
- zoom rate limit: 100% of camera distance per second
- rotation rate limit: 120 degrees per second
- dropout grace: 150 ms
- after recovery, establish a new baseline; never replay lost movement
- two-hand mode suppresses Pointer, Pinch, and Open Palm

### No-hand behavior

- Under 150 ms: retain internal state; hide/fade the pointer.
- At 150 ms: clear pointer, pinch, open-palm, and two-hand state.
- At 15 seconds: stop media tracks and return to mouse mode.
- Manual camera shutdown remains available whenever tracking is active.

## UI Feedback

- A visible screen-space pointer is shown only while a valid one-hand pointer frame exists.
- Pointer visual states distinguish tracking, target hover, pinch candidate, and pinch active.
- A subtle hit-radius ring is visible during hand control.
- Camera preview remains in the upper-left and keeps landmark overlay alignment.
- Compact status text shows Mouse, Pointer, Pinch, Open Palm, Two Hand, or No Hand; it must not obscure the knowledge space.

## Calibration Profile

Store parameters in `frontend/public/config/interaction-calibration.v1.json` with:

- schema/profile version
- coordinate convention
- confidence/dropout rules
- filter parameters
- pointer/hit parameters
- pinch thresholds/durations
- open-palm durations
- two-hand deadzones/rate limits
- no-hand auto-exit duration

Profile loading validates types and ranges and falls back to a checked-in safe default if loading fails.

## Trace Recording and Replay

Auaka owns a versioned JSON trace schema containing metadata plus canonical `HandFrame` entries. Traces contain landmarks and confidence, not camera pixels or note content. A replay harness feeds frames through the same mapper and gesture engine used at runtime.

Trace annotations support nine-point target coordinates, stationary intervals, motion onset and destination, deliberate pinch attempts, non-pinch idle intervals, expected gesture events, expected camera distance, and expected orbit angle. Metrics use these labels rather than attempting to infer user intent.

Checked-in traces should be synthetic or explicitly non-sensitive. Real calibration recordings remain ignored local artifacts unless the user deliberately promotes a sanitized fixture.

## Acceptance Gates

- Nine-point direction mapping: 100% correct over three passes of all nine labeled targets.
- Stationary jitter at 1920×1080: p95 radial distance from the median pointer position <= 12 px over each labeled 10-second interval.
- Pointer motion lag: p95 <= 100 ms, measured from labeled motion onset to the first filtered sample crossing 10% of the labeled source-to-destination displacement.
- Deliberate pinch success: >= 95% over at least 20 labeled attempts at each of near, middle, and far camera distances; false activation <= 1 per labeled idle minute; exactly one event per successful pinch.
- Three-second neutral two-hand hold: zoom drift <= 2%, rotation drift <= 2 degrees.
- Equivalent 30/60 FPS replay: final camera-distance difference <= 10% and final orbit-angle difference <= 5 degrees.
- Dropout/reorder jump: <= 5% zoom or 5 degrees rotation.
- Automated replay gates and a real-camera smoke test must both pass.

## Open-source Decision

- Adopt/reference a small MIT One Euro Filter implementation with attribution behind the Auaka interface.
- Do not embed a full hand-control application.
- Keep MediaPipe and Three.js integration behind existing project boundaries.

## Failure Behavior

- Bad profile: show a non-blocking warning and use checked-in defaults.
- Invalid frame: ignore it and advance dropout handling.
- Non-monotonic timestamp: reset the affected filter/state machine.
- Ambiguous two-hand identity: pause transform updates and re-baseline.
- Pointer presenter failure must not stop camera shutdown or mouse fallback.
